案例背景

复杂的车载软件需要对丰富多彩的真实交通环境进行建模。在这个世界里，存在各种不同类型的实体：有些是动态的，如移动的车辆和行人；有些是静态的，如固定的路障。这些障碍物虽然都有共同的属性（比如位置），但也各自拥有独特的、关键的信息：车辆有相对本车的行驶速度，而行人则可能有横向移动的趋势。如果我们为每一种属性都定义一个独立的变量（例如 vehicle_x、vehicle_speed、pedestrian_x、pedestrian_lateral_speed），代码将迅速变得混乱且难以扩展。在正式学习如何用 C++ 构建复杂数据结构之前，我们将扮演一名“系统设计师”，并向我们的“AI 技术顾问”（AIGC 工具）请教：面对这样一个复杂的数据建模需求，有没有一种更优雅、更高效的组织方式？

任务要求

通过与 AIGC 工具互动，探索并设计一个优化的、能表示多种交通参与者的数据结构。向任意一款 AIGC 工具，用自然语言清晰地描述你的数据建模需求，需求应至少包含：需要表示多种不同类型的障碍物，例如车辆 (Vehicle) 和行人 (Pedestrian)；它们都有共同的属性，例如位置；它们各自有独特的属性，车辆有**相对速度 (relative_speed)，行人有横向移动速度 (lateral_speed)**。然后要求 AIGC 为你优化这个 C++ 数据结构，使其能更有效地存储不同类型障碍物的特定信息，并分析 AIGC 的回答，观察它是如何利用你尚未学习的 C++ 工具（如 enum、struct、union）来解决这个问题的。

[提示] 本案例包含后续将学习的 enum、struct 和 union 等内容。此时不要求掌握全部语法，重点比较处理前后的数据组织方式。

案例代码、提示与输入

本案例的“代码”是我们输入给 AIGC 的提示（Prompt），以及 AIGC 返回的设计方案。输入给 AIGC 的提示如下：

你好，请扮演一名资深的 C++ 系统架构师。我正在为一个自动驾驶仿真系统设计数据结构，需要你的帮助。

我的需求是：

1. 我需要一个统一的数据结构来表示场景中所有的障碍物。
2. 障碍物有不同的类型，主要有 车辆 (Vehicle) 和 行人 (Pedestrian)。
3. 所有障碍物都有一些共同的数据，比如 ID 和二维坐标 (x, y)。
4. 不同类型的障碍物还有各自独特的数据：车辆需要存储它的**相对速度 (relative_speed)，是一个浮点数；行人需要存储它的横向移动速度 (lateral_speed)**，也是一个浮点数。

请为我设计一个优化的 C++ 数据结构，它应该既能清晰地表示不同类型的障碍物，又能在内存使用上尽可能高效。
运行效果与分析

AIGC 生成的解决方案（示例）如下：

// 好的，作为一名C++系统架构师，我推荐使用"标签化联合体" (Tagged Union) 的设计模式来解决你的问题

// 这种设计既清晰又高效

#include <cstdint> // 为了使用 int32_t 等定长类型

// 使用强类型枚举 (enum class) 来定义障碍物的类型"标签"
// 这比使用普通的整数或宏更安全、更清晰
enum class ObstacleType : std::uint8_t {
    VEHICLE,
    PEDESTRIAN
};

// 使用联合 (union) 来存储特定类型的数据
// union 的所有成员共享同一块内存，因为一个障碍物不可能同时是车辆又是行人，
// 这样可以极大地节省内存
union SpecificData {
    float relative_speed;  // 用于车辆
    float lateral_speed;   // 用于行人
};

// 使用结构体 (struct) 将通用数据、类型标签和特定数据聚合在一起
struct Obstacle {
    std::int32_t id;        // 通用数据：ID
    float x, y;             // 通用数据：位置坐标

    ObstacleType type;      // 关键的类型标签
    SpecificData data;      // 存储特定数据的联合体
};

现象分析：AIGC 提供了一个非常专业和标准的解决方案。通过分析它的回答，我们可以提前了解到 enum class 是一种专门用来定义“类型标签”的工具，让代码更具可读性；union 是一种能让多个变量共享同一块内存的“空间魔术师”，非常适合存储互斥的数据；struct 是一个强大的“收纳盒”，能将 enum 标签和 union 数据完美地组合在一起，形成一个统一、完整的数据结构。这个方案完美地解决了我们的需求，并为我们接下来的学习指明了清晰的方向。

cpp_simulation/simulation_examples/e_D/

原始资料给出 enum class、struct、union 的设计片段；e_D/main.cpp 补了车辆与行人对象以便运行核对。

main.cpp
// 使用标签化联合体表达不同的数据类型

#include <cstdint>
#include <iostream>

enum class ObstacleType : std::uint8_t {
    VEHICLE,
    PEDESTRIAN
};

union SpecificData {
    float relative_speed;
    float lateral_speed;
};

struct Obstacle {
    std::int32_t id;
    float x;
    float y;
    ObstacleType type;
    SpecificData data;
};

int main() {
    Obstacle vehicle{1, 12.5f, 1.0f, ObstacleType::VEHICLE, {8.2f}};
    Obstacle pedestrian{2, 6.0f, -0.5f, ObstacleType::PEDESTRIAN, {1.3f}};

    std::cout << "Vehicle " << vehicle.id << ": relative speed = "
              << vehicle.data.relative_speed << " m/s" << std::endl;
    std::cout << "Pedestrian " << pedestrian.id << ": lateral speed = "
              << pedestrian.data.lateral_speed << " m/s" << std::endl;
    return 0;
}
