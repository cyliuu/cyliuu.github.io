案例背景

在编写任何复杂的代码之前，专业的工程师会先进行“设计”——规划程序的逻辑流程，就像建筑师在动工前必须先绘制蓝图一样。如果没有清晰的蓝图，直接施工（编码）很容易导致逻辑混乱、结构不稳，最终返工。程序流程图和伪代码就是我们程序员的“蓝图”。自动泊车是一个复杂的逻辑过程，它包含了顺序执行的动作、根据传感器信息做出的判断、以及持续调整直到满足条件的重复操作。在本案例中，你将扮演一名“算法规划师”，你的任务不是写 C++ 代码，而是用自然语言向你的“AI 助手”（AIGC 工具）清晰地描述一个简化的自动泊车场景，并要求它为你生成一份专业的“施工蓝图”（流程图或伪代码）。这将是你第一次在编码前，对一个完整的逻辑流进行宏观设计。

任务要求

通过与 AIGC 工具互动，为简化自动泊车场景生成一份清晰的流程图或伪代码。场景描述应包含车辆动作的顺序、基于传感器信息的判断，以及重复执行直到满足条件的循环；随后分析生成结果中三种基本程序结构的对应部分。

案例代码、提示与输入

本案例的代码是我们输入给 AIGC 的提示（Prompt），以及 AIGC 返回的规划方案。输入给 AIGC 的提示（Prompt）：

我需要你扮演一名算法规划师。请为下面这个简化的自动泊车场景，生成一份清晰的伪代码。

场景描述：

1. 车辆开始时，先向前缓慢行驶。
2. 车辆需要不断地用右侧传感器检测车位。
3. 一旦检测到宽度合适的车位，就立即停车。
4. 然后，向右打满方向盘，开始缓慢倒车。
5. 在倒车时，需要不断地用后方传感器检测车位后方的障碍物距离。
6. 如果距离障碍物太近（比如小于0.3米），就必须立刻停车，并提示“泊车失败”。
7. 否则，就继续倒车，同时用侧方传感器检测车身是否与车位线平行。
8. 一直重复倒车和检测，直到车身与车位线平行，就停车。
9. 最后，回正方向盘，并提示“泊车完成”。

        结束如果

        使用侧方传感器检测车身平行状态
    结束循环 // <--- 这是“循环”结构

现象分析：这份伪代码虽然不是 C++ 代码，但它用结构化的语言清晰地展现了整个泊车逻辑。我们可以轻易地从中识别出：
（1）顺序结构：例如，“启动引擎”→“向前行驶”→“停车”。
（2）选择结构：如果 (距离 < 0.3米) 则 ... 否则 ...，这是一个典型的判断分支。
（3）循环结构：循环 (当车身未与车位线平行时) ... 结束循环，这是一个重复执行的动作。
