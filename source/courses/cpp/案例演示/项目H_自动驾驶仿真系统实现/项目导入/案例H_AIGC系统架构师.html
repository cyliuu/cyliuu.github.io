案例背景

从独立的函数到功能完善的类，我们已经掌握了构建软件“零件”的各种技能。然而，一个真正强大、可靠的软件系统，远不止是简单地将所有零件堆砌在一起。它更像一座精心设计的建筑，需要有明确的承重墙（核心模块）、功能分区（子系统）和统一的入口（主控逻辑）。在将所有模块集成为一个协同工作的整体之前，必须进行顶层的“架构设计”。在这一最终阶段，我们将扮演一名“系统架构师”，并邀请 AIGC 作为我们的高级技术顾问。我们的任务不再是实现某个具体功能，而是从宏观视角出发，为一个复杂的系统规划其“四梁八柱”。我们将学习如何运用软件设计模式——这些被无数前辈工程师验证过的、解决特定问题的“最佳实践”——来指导我们的设计。这将是我们从“程序员”向“架构师”角色转变的第一次思想预演。

任务要求

使用 AIGC 工具为命令行自动驾驶仿真系统设计合理的类结构和关系：以自然语言说明可移动车辆、表示环境的地图和固定障碍物等核心组件，要求工具给出 C++ 类关系及可能采用的设计模式，并分析其如何将复杂需求分解为职责清晰、相互协作的类。

案例代码、提示与输入

本案例的“代码”是我们输入给 AIGC 的提示（Prompt），以及 AIGC 返回的架构设计方案。输入给 AIGC 的提示如下：

我需要你扮演一名资深的C++软件系统架构师。请为我设计一个简单的、基于命令行的“自动驾驶仿真系统”的顶层架构。

系统需求如下：

1. 系统需要有一个主控中心，负责管理和驱动整个仿真流程。
2. 系统中要有一个可以移动的 **Vehicle（车辆）**对象。
3. 系统需要一个 **Map（地图）**对象，用于描述道路环境。
4. 地图上可以放置多个 **Obstacle（障碍物）**对象。
5. 主控中心需要能整合这些模块，模拟车辆根据地图和障碍物信息进行移动的简单逻辑。

你的任务是：

1. 为这个系统设计一套合理的C++类结构，并画出它们之间的关系（用文字描述即可）。
2. 为每个核心类提供一个简单的头文件定义（.h文件内容）。
3. 解释你的设计中可能应用了哪些常见的软件设计模式，并说明为什么。
运行效果与分析

AIGC 生成的架构设计方案（示例）：好的，作为一名系统架构师，我为您设计了一套基于“关注点分离”和常见设计模式的 C++ 架构。我建议使用一个名为 SimulationSystem 的核心类来作为系统的“主控中心”，它将“拥有”并管理 Vehicle、Map、ObstacleManager 等子系统。这种设计清晰地分离了各个模块的职责。核心类头文件定义如下：

class Obstacle { /* ... 障碍物的基础属性 ... */ };

#include <vector>
#include "Obstacle.h"
class ObstacleManager {
public:
    void load_obstacles();
private:
    std::vector<Obstacle> obstacles_;
};

class Map { /* ... 地图数据和方法 ... */ };

class Vehicle { /* ... 车辆的属性和行为 ... */ };

// SimulationSystem.h (核心主控类)
#include "Vehicle.h"
#include "Map.h"
#include "ObstacleManager.h"

class SimulationSystem {
public:
    void initialize(); // 初始化所有子系统
    void run_simulation_step(); // 运行一个仿真步长
    bool is_finished() const;

private:
    Vehicle         ego_vehicle_;
    Map             world_map_;
    ObstacleManager obstacle_manager_;
};

应用的设计模式：外观模式（Facade Pattern），SimulationSystem 类是这个模式的完美体现，它为整个复杂的仿真子系统（车辆、地图、障碍物管理）提供了一个简化的、统一的入口，外部调用者（例如 main 函数）只需要与 SimulationSystem 交互，调用 initialize() 和 run_simulation_step() 即可，而无需关心其内部各个模块之间复杂的调用关系；单例模式（Singleton Pattern，可选），如果整个应用程序在任何时候都只允许存在一个仿真实例，那么可以将 SimulationSystem 设计为单例模式，确保全局只有一个仿真的“世界”，避免多个仿真实例造成的状态冲突。现象分析：AIGC 没有直接开始写实现，而是先进行了顶层设计，定义了各个模块和它们之间的关系；它提出的 SimulationSystem 核心类，正是将所有子系统整合起来的关键，体现了“高内聚、低耦合”的设计思想；AIGC 能够准确识别并应用软件设计模式（如外观模式）来解释其设计思路，这表明了设计模式是解决特定架构问题的“通用语言”。

main.cpp
#include "SimulationSystem.h"

int main() {
    SimulationSystem simulation;
    simulation.initialize();

    while (!simulation.is_finished()) {
        simulation.run_simulation_step();
    }
    return 0;
}
SimulationSystem.h
#pragma once

#include "Map.h"
#include "ObstacleManager.h"
#include "Vehicle.h"

class SimulationSystem {
public:
    void initialize();
    void run_simulation_step();
    bool is_finished() const;

private:
    Map map_;
    ObstacleManager obstacle_manager_;
    Vehicle ego_vehicle_{1, 0.0, 36.0};
    int completed_steps_ = 0;
};
SimulationSystem.cpp
#include "SimulationSystem.h"

#include <iostream>

void SimulationSystem::initialize() {
    map_.load_default_scene();
    obstacle_manager_.add_obstacle({101, 40.0});
    std::cout << "加载地图：" << map_.road_name() << '\n';
    std::cout << "已加载障碍物数量：" << obstacle_manager_.count() << '\n';
}

void SimulationSystem::run_simulation_step() {
    ego_vehicle_.advance(1.0);
    ++completed_steps_;
    std::cout << "第 " << completed_steps_ << " 步：车辆位置 "
              << ego_vehicle_.position_m() << " m" << '\n';
}

bool SimulationSystem::is_finished() const {
    return completed_steps_ >= 3;
}
