情境背景

在大型车载软件系统的开发中，不同团队通常负责不同的模块。例如，一个“核心物理引擎”团队负责开发所有仿真对象（如障碍物）的底层通用功能，比如提供一个独一无二的 ID 和更新其物理位置的方法；而“应用逻辑”团队则基于这些底层功能，开发具体的障碍物类型。为了保证系统的稳定性和安全性，核心团队不希望应用团队的工程师随意调用底层的、原始的函数，而是希望他们通过封装好的、更高级的接口来交互。这就引入了一个新问题：如何既能让派生类“继承”并“使用”基类的功能，又能“隐藏”这些功能，不让外部代码直接访问？保护继承正是为此场景而设计的。

案例要求

模拟 MovingObstacle 复用 BaseObstacle 实现但不完全暴露其公共接口的场景：BaseObstacle 包含公共 get_id()、以 Point 表示的受保护 position 与受保护 update_position()；MovingObstacle 以 protected 方式继承，提供 advance_one_step() 间接调用更新函数，并以 get_tracking_id() 选择性重新暴露 ID 查询。在 main 中验证只能调用派生类自身的公共函数，不能直接调用基类 get_id()。
源码核对重点：protected 继承改变继承成员对外的可访问性；案例通过 get_tracking_id 暴露必要信息。

#include <iostream>

// 用于表示二维坐标的简单结构体
struct Point {
    double x = 0.0;
    double y = 0.0;
};

// 基类：提供所有障碍物的基础功能
class BaseObstacle {
public:
    // 构造函数：初始化 ID 和位置
    BaseObstacle(int id, Point pos) : unique_id(id), position(pos) {}

    // 公共接口：获取对象的唯一 ID
    int get_id() const {
        return unique_id;
    }

protected:
    // 受保护的成员：派生类可以访问，但外部不行
    Point position;
    int unique_id;

    // 受保护的方法：只允许派生类在内部调用，用于更新状态
    void update_position(double dx, double dy) {
        position.x += dx;
        position.y += dy;
    }
};

// 派生类：使用保护继承
// 这意味着BaseObstacle的public和protected成员，
// 在MovingObstacle内部都变成了protected
class MovingObstacle : protected BaseObstacle {
public:
    // 派生类构造函数，调用基类构造函数
    MovingObstacle(int id, Point pos, double spd) 
        : BaseObstacle(id, pos), speed(spd) {}

    // 派生类提供的高级公共接口
    void advance_one_step() {
        // 在内部，它可以调用继承来的受保护方法
        update_position(speed * 0.1, 0); // 模拟向前移动
        std::cout << "障碍物 " << unique_id << " 前进了一步，新位置: (" 
                  << position.x << ", " << position.y << ")" << std::endl;
    }

    // 派生类可以选择性地将基类的某个接口重新暴露为public
    int get_tracking_id() const {
        // 在内部，它可以访问继承来的受保护成员和方法
        return get_id(); 
    }

private:
    double speed;
};

int main() {
    MovingObstacle car(101, {50.0, 1.0}, 60.0);

    // 调用派生类自己定义的 public 方法 -> 成功
    std::cout << "--- 派生类接口测试 ---" << std::endl;
    std::cout << "通过派生类接口获取ID: " << car.get_tracking_id() << std::endl;
    car.advance_one_step();
    car.advance_one_step();

    // 尝试调用基类的 public 方法 -> 失败
    std::cout << "\n--- 访问控制测试 ---" << std::endl;
    // 下面的代码行会导致编译错误
    // int id = car.get_id();
    // 错误信息: 'BaseObstacle' is an inaccessible base of 'MovingObstacle'
    // 'get_id' is a member of 'BaseObstacle'
    std::cout << "尝试直接调用 car.get_id() ... 编译失败！" << std::endl;
    std::cout << "这证明了'protected'继承成功地将基类的public接口隐藏了。" << std::endl;

    return 0;
}
