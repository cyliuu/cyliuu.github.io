情境背景

在大型的软件项目中，代码通常被组织成多个独立的模块（例如，一个专门负责数学运算的 math_utils 模块，一个负责日志记录的 logging 模块等）。每个模块都会包含一些对外提供服务的公共接口函数，同时也会有一些只在模块内部使用的辅助函数。一个常见的工程问题是：如果 math_utils 模块内部有一个辅助函数叫 is_valid()，而 logging 模块内部也有一个同名的辅助函数，当链接器最终将所有模块组合在一起时，就会发现两个同名的函数，从而导致“多重定义”的链接错误。为了解决这个问题，并实现良好的信息隐藏，我们需要一种机制来明确地告诉编译器：这个函数是本模块的“内部秘密”，不应该被外部世界看到。静态函数正是实现这一目标的关键工具。

案例要求

通过创建一个简单的数学工具模块，来实践如何使用静态函数封装内部实现，并与外部函数进行区分。创建一个多文件项目，包含 math_utils.h、math_utils.cpp 和 main.cpp；在 math_utils.h 中，声明一个对外公开的外部函数 double average(const double arr[], int size)，用于计算数组的平均值；在 math_utils.cpp 中，定义 average 函数，并定义一个静态函数 static double sum(const double arr[], int size)，它只用于辅助 average 函数计算数组总和，static 关键字将确保此函数只在 math_utils.cpp 文件内部可见；在 main.cpp 中，成功调用外部函数 average，并尝试声明并调用静态函数 sum，观察并理解为什么这会导致链接错误。
源码核对重点：命名空间作用域的 static 为内部链接，不是类的 static 成员；average 经头文件声明可供 main.cpp 调用。

#define MATH_UTILS_H

// 这是一个外部函数（默认），其声明对所有包含此头文件的文件都可见
// 功能：计算一个double数组的平均值
double average(const double arr[], int size);

#endif // MATH_UTILS_H
ee_45/math_utils.cpp
// 实现了math_utils模块的功能

#include "math_utils.h"

// 定义一个静态函数 (内部链接)
// static 关键字将 sum 函数的作用域限制在当前源文件
//    其他.cpp文件即使声明了它，也无法在链接时找到它
static double sum(const double arr[], int size) {
    double total = 0.0;
    for (int i = 0; i < size; ++i) {
        total += arr[i];
    }
    return total;
}

// 定义外部函数 (外部链接)
//    这个函数是模块的公共接口
double average(const double arr[], int size) {
    if (size <= 0) {
        return 0.0;
    }
    // 在内部调用同文件下的静态辅助函数
    return sum(arr, size) / size;
}
