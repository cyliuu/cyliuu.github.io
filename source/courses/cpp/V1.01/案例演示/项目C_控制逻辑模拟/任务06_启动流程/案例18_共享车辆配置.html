情境背景

随着一个软件项目逐渐壮大，我们开始将不同功能的代码拆分到不同的文件中（模块化）。例如，main.cpp 负责主流程，vehicle.cpp 负责车辆自身的逻辑，而 config.cpp 可能专门存放项目的全局配置参数。现在出现了一个新需求：我们希望在 config.cpp 中定义一个全局的“驾驶模式”（如 "ECO" 经济模式），并且在 main.cpp 中能够读取并使用这个配置，而无需将其作为参数传来传去。如果 main.cpp 直接尝试使用一个在别的文件中定义的变量，编译器会报错说“未定义”。为了解决这个问题，我们需要一种机制来“通知”编译器：“我要使用的这个变量是真实存在的，只不过它定义在别的文件里，请在最后链接时帮我找到它”。C++ 提供了 extern 关键字来做出这个重要的“外部声明”。

案例要求

编写一个包含 config.cpp 和 main.cpp 的多文件 C++ 项目，模拟模块间共享全局配置：在 config.cpp 中定义值为 "ECO" 的全局常量 const char* VEHICLE_MODE，在 main.cpp 中不包含 config.cpp，而以 extern 声明该变量并在 main 中打印其值。
源码核对重点：extern 声明不分配该变量的唯一实体；定义在另一个翻译单元，必须一起链接。

ee_18/main.cpp
// 程序主入口，它需要使用在 config.cpp 中定义的配置

#include <iostream>

// 声明
// extern 声明引用在 config.cpp 中定义的配置变量
// "请注意，有一个名为 VEHICLE_MODE 的 const char* 变量，
//  但它不在这里定义，请相信我，链接器会在别的某个地方找到它。"
// "extern" 声明可以有很多份，分布在需要使用该变量的各个文件中
extern const char* VEHICLE_MODE;

int main() {
    std::cout << "--- 车辆配置共享演示 ---" << std::endl;

    // 直接使用这个在外部定义的变量
    // 编译器在编译 main.cpp 时，因为它看到了 extern 声明，所以不会报错
    // 在最后的链接阶段，链接器会把这里的引用，和 config.cpp 中的定义关联起来
    std::cout << "从主程序(main.cpp)读取到当前的驾驶模式为: "
              << VEHICLE_MODE << std::endl;

    return 0;
}
