案例任务与源码核对

情境背景

车载控制器局域网（CAN 总线）是现代汽车的“神经网络”，上面实时传递着成百上千条指令和状态信息。在进行系统诊断或性能监控时，一个常见的任务是统计某个特定的函数或模块被调用的次数，例如，“CAN 总线消息接收模块”在 1 秒内被触发了多少次。如果我们使用普通的局部变量来做计数器，那么每次进入这个模块时，计数器都会被重置为 0，这显然无法完成累计计数的任务。我们需要一种特殊的变量，它既有局部变量的“私有性”（只能在模块内部访问），又要有全局变量的“长久生命”，能够在多次调用之间保持并记忆自己的值。C++ 中的 static 关键字正是解决这一问题的关键。

案例要求

编写一个 C++ 程序模拟持续监听 CAN 总线消息，并比较普通局部变量和静态局部变量的计数差异。定义 receive_can_message() 模拟接收消息，在其中分别定义 static int static_message_count 与普通 int normal_message_count，每次调用都将二者加一并打印；在 main 中连续调用 5 次，观察两种计数器的输出差异。
源码核对重点：函数局部 static 对象只初始化一次，五次调用可依次计数；普通局部变量每次进入函数重新初始化。

ee_17/main.cpp
// 观察静态局部变量的生命周期

#include <iostream>

// 我们将用这个函数来模拟"接收到一条CAN消息"的动作
// 函数是C++中用于封装功能的代码块，我们将在后续课程中深入学习
// 现在，请将它看作一个可以被重复呼叫的"小模块"
void receive_can_message() {
    // 定义一个普通的局部变量作为计数器
    int normal_message_count = 0;
    normal_message_count++;

    // 定义一个静态的局部变量作为计数器
    // static 使局部变量在函数调用之间保持状态
    // 它告诉编译器：
    // a) 这个变量的初始化( = 0 )只在程序第一次运行到这里时执行一次
    // b) 函数结束后，不要销毁这个变量，让它继续"活在"内存里
    static int static_message_count = 0;
    static_message_count++;

    std::cout << "普通计数器: " << normal_message_count
              << "\t | \t静态计数器: " << static_message_count << std::endl;
}

int main() {
    std::cout << "模拟连续接收5条CAN总线消息..." << std::endl;

    // 连续5次调用函数，模拟事件的发生
    receive_can_message(); // 第1次调用
    receive_can_message(); // 第2次调用
    receive_can_message(); // 第3次调用
    receive_can_message(); // 第4次调用
    receive_can_message(); // 第5次调用

    return 0;
}
