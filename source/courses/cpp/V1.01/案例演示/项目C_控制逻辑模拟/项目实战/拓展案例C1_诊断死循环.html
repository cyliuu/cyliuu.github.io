情境背景

在软件开发中，无论多么经验丰富的工程师都难免会犯错，而“死循环”（Infinite Loop）是最常见的逻辑错误之一。一个陷入死循环的程序会持续执行，耗尽 CPU 资源，导致程序卡死、无响应，甚至可能使整个车载系统崩溃。当一个可执行文件运行起来却没有任何反应时，它就像一个“黑盒子”，我们无法知道其内部发生了什么。作为开发者，我们的首要任务就是成为一名“诊断医生”，利用最基本、最可靠的工具来打开这个“黑盒子”，观察内部状态，从而定位并修复问题。本案例将教你如何使用最原始但极其有效的调试方法——打印日志，来诊断并修复一个由错误循环条件导致的死循环。

案例要求

编写一个 C++ 程序故意制造死循环，并通过打印语句定位错误：编写本意循环 10 次却将 for 更新表达式 i++ 误写为 i-- 的循环，先直接运行并观察卡死现象；随后在循环中加入 std::cout 打印 i，根据其持续变化分析无法终止的原因，修复错误并验证程序能够正常结束。
源码核对重点：教学上可观察到条件无法按预期趋向结束；若有符号 int 一直递减至溢出，实际 C++ 行为未定义，因此网页只演示有限步并提示风险。

// 一个包含死循环的程序

#include <iostream>

int main() {
    std::cout << "程序开始，准备进入循环..." << std::endl;

    // 错误的循环：更新条件是 i--，导致 i 永远不可能大于等于 10
    for (int i = 0; i < 10; i--) {
        // 因为循环体内部没有任何输出，所以程序看起来就像"卡住"了
        // （实际上它在疯狂地执行，只是我们看不到）
    }

    // 这行代码永远不会被执行到
    std::cout << "程序正常结束。" << std::endl;

    return 0;
}
eee_C1/variant_2/main_debug.cpp
// 使用打印语句来诊断死循环

#include <iostream>
#include <chrono>
#include <thread>

int main() {
    std::cout << "程序开始，准备进入循环..." << std::endl;

    for (int i = 0; i < 10; i--) {
        // 诊断代码
        // 在循环内部打印变量 i，观察循环条件是否变化
        // 这就像在机器内部安装了一个"监视器"
        std::cout << "当前 i 的值是: " << i << std::endl;

        // 减慢输出速度，便于观察变量变化
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }

    std::cout << "程序正常结束。" << std::endl;

    return 0;
}
