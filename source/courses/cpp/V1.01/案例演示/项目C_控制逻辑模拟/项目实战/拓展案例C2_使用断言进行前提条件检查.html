案例任务与源码核对

情境背景

使用“打印”是一种常见的、被动的诊断程序问题的方式，它能帮助我们在问题发生之后去回溯和分析。但这就像是等问题发生后才去补救。有没有一种更主动、更“强硬”的方法，能够在错误发生的瞬间就让程序停下来，防止其带着错误的状态继续执行，造成更大的破坏呢？例如，一个负责计算轮胎压力的模块，其输入压力值按物理规则必须是正数。如果因为其他地方的逻辑错误，导致一个负数值被传了进来，那么后续的计算都将是无意义的，甚至可能引发更严重的问题。断言（Assertion）就是我们设置在代码中的“哨兵”，它以契约的形式规定：“我断定，执行到这里时，这个条件必须为真！如果不是，那一定是程序出了 BUG，请立刻停下，不要再继续造成破坏了！”。本案例将教你如何使用 assert 来捍卫代码的正确性。

案例要求

编写一个 C++ 程序将轮胎压力从 PSI（磅/平方英寸）转换为 bar（1 PSI ≈ 0.0689 bar），并在转换前使用 assert(psi > 0); 确保输入为正数。分别以合法的正数和非法的负数运行，观察正常输出以及断言中断程序并报告错误的效果。
源码核对重点：assert(psi>0) 是调试期前提检查；定义 NDEBUG 时断言可能被移除，不能依赖它完成正式输入校验。

// 使用 assert 检查输入前提条件

#include <iostream>
#include <cassert> // 提供 assert 宏

int main() {
    // 场景 1：使用合法的输入值
    // double tire_pressure_psi = 32.5; // 一个正常的轮胎压力值

    // 场景 2：使用非法的输入值
    // 为了触发断言，使用一个非法的负数值
    double tire_pressure_psi = -5.0;

    std::cout << "--- 轮胎压力单位转换 ---" << std::endl;
    std::cout << "输入的PSI值: " << tire_pressure_psi << std::endl;

    // 设置断言，检查输入值是否为正数
    // assert() 在条件为真时继续执行，在条件为假时终止程序并输出诊断信息
    assert(tire_pressure_psi > 0);

    // 仅在断言通过后执行压力转换
    double pressure_in_bar = tire_pressure_psi * 0.0689;
    std::cout << "转换后的压力为: " << pressure_in_bar << " bar" << std::endl;

    std::cout << "程序正常结束。" << std::endl;

    return 0;
}
